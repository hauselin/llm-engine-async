# Replace litellm with direct OpenRouter calls (2026-08-25)

## Decision
Drop `litellm`; call `https://openrouter.ai/api/v1/chat/completions` directly with `httpx.AsyncClient`.

- litellm was never in `pyproject.toml`/`uv.lock`, so the scripts did not run before this change.
- New dependency: `httpx` 0.28.1 (`uv add httpx`).

## Changes
- `src/llm_engine.py`
  - `openrouter_chat(model, messages, response_model=None, num_retries=3, **extra_body)`:
    shared `httpx.AsyncClient`; sends `usage: {include: true}` so `usage.cost` is returned;
    Pydantic model -> strict `json_schema` `response_format`; retries on 408/429/5xx,
    network errors, and 200-with-`error` payloads (exponential backoff, cap 30s).
  - Pydantic `ModelResponse`/`Choice`/`Message`/`Usage` (extra fields kept), `OpenRouterError`;
    `response_ms` measured client-side.
  - `setup_litellm()` -> `setup_env()`; checks only `OPENROUTER_API_KEY`.
- `src/process/factcheck.py`: uses `openrouter_chat`; `tools=[...]` passed directly;
  model ids drop the litellm `openrouter/` prefix (asserted).
- `src/utils.py`: deleted 2026-08-25 15:07 (nothing imported it).
- `src/llm_engine.md`: examples updated.

## httpx vs aiohttp
httpx chosen: simpler API (no `async with session.post(...)` nesting), sync + async in one API
(usable in notebooks), full type hints (clean `ty`), pure Python (no C extensions to build on
Python 3.14), same client the OpenAI SDK uses. aiohttp is ~1.5-3x faster per request on tiny
payloads (C parser) — irrelevant when each request waits seconds on the LLM.

## Connection pool caveat (must fix)
- httpx defaults: HTTP/1.1, `max_connections=100`, `max_keepalive_connections=20`.
- Overflow requests queue FIFO inside httpcore (`AsyncConnectionPool._assign_requests_to_connections`
  walks pending requests in insertion order).
- The queue wait is bounded by the `pool` timeout (default 5s). With `BATCH_SIZE = 200` and
  multi-second LLM calls, ~100 requests exceed 5s in the queue and raise `PoolTimeout`,
  hitting the retry path. NOT harmless.
- Fix: `httpx.AsyncClient(timeout=httpx.Timeout(180.0, connect=10.0), limits=httpx.Limits(max_connections=None))`
  so the `run_batch` semaphore is the single concurrency limit.
  Alternative: `pool=None` in `httpx.Timeout`, or `max_connections=BATCH_SIZE`.
